## Scope: the indexed-loop gap remaining after iterator and dead-admission costs

The public short-scan repro for #13645 still has a large gap with indexed access. #13660 now isolates a separate unused packed-loop admission triggered by `j++`. This report holds the increment at **`j += 1`** so that artifact does not explain the remaining measurements.

For five million identical probes:

- Live-length indexed scan: Perry **266.64 ms**, Node **45.99 ms**; **784.03 vs 173.95 incremental instructions/probe**.
- Fixed bound, same array element reads and same increment: Perry **246.42 ms**, **667.31 instructions/probe**. This saves **116.72 instructions/probe** (~15% of the Perry live-bound instruction budget), while Node's instruction cost remains ~174.
- Same fixed loop and ordinary board array, but compute the eight constant directions instead of loading them: Perry **131.27 ms**, **410.00 instructions/probe**. This saves a further **257.31 instructions/probe** (~39% of the fixed-bound instruction budget).
- Even the direction-arithmetic form remains **410 vs 150.77 instructions/probe**, and **131.27 vs 53.38 ms**, against Node.

These are **controlled source reductions**, not additive allocations of the full application runtime to individual helpers. Arithmetic direction generation changes the work done; it exposes an optimization opportunity but is not an instruction-for-instruction implementation of an array read. The fixed bound is valid for this immutable fixture, not for arbitrary mutable arrays.

```typescript
// Synthetic numeric-array access reduction; contains no application source.
// Each variant visits the same cells in the same order and returns early on 2.
const STEPS: number[] = [-17, -16, -15, -1, 1, 15, 16, 17];
const TYPED_STEPS = new Int32Array([-17, -16, -15, -1, 1, 15, 16, 17]);
class AccessBoard {
  cells: number[] = new Array<number>(128).fill(0);
  typed: Int32Array = new Int32Array(128);
  constructor() {
    for (let i = 0; i < 128; i++) {
      const value = (i & 0x88) === 0 ? ((i * 3) % 7) - 3 : 0;
      this.cells[i] = value;
      this.typed[i] = value;
    }
  }
  at(square: number): number { return this.cells[square] ?? 0; }
  method(origin: number): boolean {
    for (let j = 0; j < STEPS.length; j++) {
      const square = origin + (STEPS[j] ?? 0);
      if (square >= 0 && square < 128 && (square & 0x88) === 0 && this.at(square) === 2) return true;
    }
    return false;
  }
  field(origin: number): boolean {
    for (let j = 0; j < STEPS.length; j++) {
      const square = origin + (STEPS[j] ?? 0);
      if (square >= 0 && square < 128 && (square & 0x88) === 0 && (this.cells[square] ?? 0) === 2) return true;
    }
    return false;
  }
  local(origin: number): boolean {
    const cells = this.cells;
    for (let j = 0; j < STEPS.length; j++) {
      const square = origin + (STEPS[j] ?? 0);
      if (square >= 0 && square < 128 && (square & 0x88) === 0 && (cells[square] ?? 0) === 2) return true;
    }
    return false;
  }
  liveBound(origin: number): boolean {
    const cells = this.cells;
    for (let j = 0; j < STEPS.length; j += 1) {
      const square = origin + (STEPS[j] ?? 0);
      if (square >= 0 && square < 128 && (square & 0x88) === 0 && (cells[square] ?? 0) === 2) return true;
    }
    return false;
  }
  typedLocal(origin: number): boolean {
    const cells = this.typed;
    for (let j = 0; j < STEPS.length; j++) {
      const square = origin + (STEPS[j] ?? 0);
      if (square >= 0 && square < 128 && (square & 0x88) === 0 && (cells[square] ?? 0) === 2) return true;
    }
    return false;
  }
  directions(origin: number): boolean {
    const cells = this.cells;
    for (let j = 0; j < 8; j += 1) {
      const delta = j < 3 ? j - 17 : j < 5 ? 2 * j - 7 : j + 10;
      const square = origin + delta;
      if (square >= 0 && square < 128 && (square & 0x88) === 0 && (cells[square] ?? 0) === 2) return true;
    }
    return false;
  }
  fixedBound(origin: number): boolean {
    const cells = this.cells;
    for (let j = 0; j < 8; j += 1) {
      const square = origin + (STEPS[j] ?? 0);
      if (square >= 0 && square < 128 && (square & 0x88) === 0 && (cells[square] ?? 0) === 2) return true;
    }
    return false;
  }
  fixedTyped(origin: number): boolean {
    const cells = this.cells;
    for (let j = 0; j < 8; j += 1) {
      const square = origin + (TYPED_STEPS[j] ?? 0);
      if (square >= 0 && square < 128 && (square & 0x88) === 0 && (cells[square] ?? 0) === 2) return true;
    }
    return false;
  }
  arithmetic(origin: number): boolean {
    // Same-answer control only: computes this fixture's immutable cell value.
    // It cannot replace reading the mutable board in the real chess engine.
    for (let j = 0; j < 8; j += 1) {
      const delta = j < 3 ? j - 17 : j < 5 ? 2 * j - 7 : j + 10;
      const square = origin + delta;
      if (square >= 0 && square < 128 && (square & 0x88) === 0 && ((square * 3) % 7) - 3 === 2) return true;
    }
    return false;
  }
}
function flat(cells: number[], origin: number): boolean {
  for (let j = 0; j < STEPS.length; j++) {
    const square = origin + (STEPS[j] ?? 0);
    if (square >= 0 && square < 128 && (square & 0x88) === 0 && (cells[square] ?? 0) === 2) return true;
  }
  return false;
}
function scan(board: AccessBoard, amount: number, variant: string): number {
  let sum = 0;
  // Select the variant outside the timed hot loop: no per-probe mode branch.
  if (variant === "method") {
    for (let i = 0; i < amount; i++) if (board.method(i & 127)) sum++;
  } else if (variant === "field") {
    for (let i = 0; i < amount; i++) if (board.field(i & 127)) sum++;
  } else if (variant === "local") {
    for (let i = 0; i < amount; i++) if (board.local(i & 127)) sum++;
  } else if (variant === "live-bound") {
    for (let i = 0; i < amount; i++) if (board.liveBound(i & 127)) sum++;
  } else if (variant === "typed-local") {
    for (let i = 0; i < amount; i++) if (board.typedLocal(i & 127)) sum++;
  } else if (variant === "flat") {
    const cells = board.cells;
    for (let i = 0; i < amount; i++) if (flat(cells, i & 127)) sum++;
  } else if (variant === "directions") {
    for (let i = 0; i < amount; i++) if (board.directions(i & 127)) sum++;
  } else if (variant === "arithmetic") {
    for (let i = 0; i < amount; i++) if (board.arithmetic(i & 127)) sum++;
  } else if (variant === "fixed-bound") {
    for (let i = 0; i < amount; i++) if (board.fixedBound(i & 127)) sum++;
  } else if (variant === "fixed-typed") {
    for (let i = 0; i < amount; i++) if (board.fixedTyped(i & 127)) sum++;
  } else throw new Error("Unknown access variant");
  return sum;
}
const variant = process.argv[2] ?? "method";
const amount = Number(process.argv[3] ?? "5000000");
if (!Number.isSafeInteger(amount) || amount <= 0) throw new Error("Expected a positive iteration count");
const board = new AccessBoard();
const warmup = scan(board, 100000, variant);
const started = performance.now();
const checksum = scan(board, amount, variant);
const milliseconds = performance.now() - started;
console.log(JSON.stringify({ variant, amount, warmup, checksum, milliseconds }));
```

## What the profile and code establish

An eight-second optimized-release sample of the indexed method form (before the extra controls were added, same source shape) collected 5,998 self samples:

| Symbol/group | Self samples | Share |
| --- | ---: | ---: |
| generated `scan` | 4,932 | 82.2% |
| `array::header::ensure_array_numeric_raw_f64` | 465 | 7.8% |
| `array::subclass::loop_guard::packed_arraylike_loop_guard` | 318 | 5.3% |
| `js_packed_arraylike_loop_guard_live` | 33 | 0.6% |
| deduplicated symbol | 250 | 4.2% |

The helper chain is now separately actionable in #13660. The 82% in generated code includes both useful arithmetic and inline checks; a symbol profile does not separate them. It must **not** be called 82% wasted work.

Inspect these pinned implementation points:

- [array index normalization](https://github.com/PerryTS/perry/blob/b384cd7be035899e80908c5013baf8e88f08c892/crates/perry-codegen/src/expr/index_key.rs): `normalize` reuses widened native integer provenance when available; otherwise it performs exact generic normalization. Inspect why bounded square/index facts are not carried far enough in this fixture.
- [numeric element proof regression tests](https://github.com/PerryTS/perry/blob/b384cd7be035899e80908c5013baf8e88f08c892/crates/perry-codegen/src/expr/array_push_guard_tests.rs): `a_declared_type_lie_is_routed_to_the_runtime_tier_not_the_guard` explains why a declared `number[]` read alone is not proof of canonical raw-f64 values. Fixes need construction/assignment or guarded representation evidence, not trust in erased TypeScript annotations.
- [packed-loop lowering](https://github.com/PerryTS/perry/blob/b384cd7be035899e80908c5013baf8e88f08c892/crates/perry-codegen/src/stmt/stable_packed_loop.rs), including the abandoned fast clone in #13660.
- [array header](https://github.com/PerryTS/perry/blob/b384cd7be035899e80908c5013baf8e88f08c892/crates/perry-runtime/src/array/header.rs#L1480): numeric layout is already an O(1) header bit after initial setup. Repeated full-array rescanning is **not** the explanation.

Related #10777 demonstrates lost read-result representation on const bindings in a property-read fixture; #10769 tracks receiver provenance. Those are relevant mechanisms to investigate, not proof that their exact fixes eliminate this array fixture's cost. The presized board here does not establish #10514's growth-forwarding cause, and these typed-array controls do not create ArrayBuffer-aliasing views, so #10516 is not established as their cause either.

## Fix targets / validation

1. Explain and reduce the **117 instructions/probe** associated with the live-bound versus fixed-bound form where immutability can actually be proved; preserve live length semantics when callbacks/writes can change it.
2. Carry proven numeric element and integer-index facts through the element read, addition, bounds comparisons and bitwise check. Use the **667 → 410 instructions/probe** fixture contrast to assess progress, not as a promised universal saving.
3. Account for the remaining generated-code cost using emitted IR/assembly and loop-size instruction slopes. A broader instruction target is the Node ~174 instructions/probe for the equivalent indexed fixture; no claim that every remaining instruction is removable.
4. Keep overrides, holes/inherited indexed getters, element descriptors, mutation, unexpected values under erased annotations, NaN/-0/overflow and moving-GC behavior correct. Test both accepted fast paths and fallback paths.
5. Re-run `method`, `local`, `live-bound`, `fixed-bound`, `fixed-typed`, `directions`, and `arithmetic`. Match checksums; do not optimize only the hand-rewritten control. Run existing native correctness and GC suites and a full application before claiming an end-to-end win.

This is an optimization issue, not an observed result mismatch. No performance regression range is established.
