# tuichess 3D

A browser version of tuichess on a 3D board, built with Three.js. You play the
tuichess engine (`@plain-chess/engine`, running in a Web Worker) with animated
3D pieces. It is also the reference that the Bloom engine port will be checked
against: the same GLB files are meant to load unchanged in Bloom.

```bash
npm install                   # at the repo root (web3d is a workspace)
cd web3d
npm run dev                   # build + serve on http://localhost:8173 (bun)
npm run build                 # static files in web3d/dist/
npm run models                # regenerate public/models/*.glb (Blender 4.4+, tested on 5.0)
npm run validate              # Khronos glTF-Validator + project conventions
```

## The pieces

All six pieces are generated by one script, `models/pieces.py`, run headless
in Blender. To change proportions, edit the profiles in that script and run
`npm run models`. To render the lineup from the front and the side for a quick
look:

```bash
blender -b --factory-startup --python models/pieces.py -- --preview /tmp/pieces.png
```

### Conventions

The web version and Bloom both rely on these:

| | |
|---|---|
| Units | 1 unit = 1 board square. Heights: pawn .58, rook .73, knight .95, bishop .90, queen 1.03, king 1.2 |
| Axes | glTF Y-up. The origin is the center of the base and the piece stands on y = 0 |
| Facing | The front (the knight's muzzle) faces +Z |
| Mesh | One skinned mesh per piece, about 8–13k triangles, at most 2 bone weights per vertex |
| Rig | Three bones in a chain: `root` (base) → `body` → `head` |
| Morph targets | None. Bloom doesn't play them, so all motion is done with bones |
| Materials | `Body` has a white base color: tint it at runtime or give it textures. `Felt` is the underside |
| UVs | `TEXCOORD_0` is a non-overlapping atlas in 0–1 with even texel density. Tangents are exported, so normal maps work straight away |

### Clips

The clips are baked every frame at 30 fps. They only animate the bones: the
game moves the piece object itself, and the root bone's offsets are relative
to its square.

| Index | Name | Length | Use |
|---|---|---|---|
| 0 | `idle` | 3.0 s, loops | Gentle breathing and a slow head sway |
| 1 | `select` | 1.0 s, loops | Wobble while a piece is picked up |
| 2 | `hop` | 0.9 s | Squash and stretch for a move. The game moves the piece along its arc between **takeoff 0.24 s** and **land 0.60 s** |
| 3 | `captured` | 1.1 s | Recoil, then topple backward on the rim of the base (away from +Z) and come to rest. Hold the last frame |
| 4 | `celebrate` | 1.6 s | Two hops in place with a full spin |

Bloom addresses clips by index (`animPlay(handle, clip, fade)`), so the
validator enforces this order. The timings are also in the armature node's
glTF extras (`"tuichess"`), which the web version reads. Bloom can't read
extras, so use the constants from this table there. Bloom keeps root-bone
translation in the pose by default (root motion is off), which the `captured`
and `celebrate` clips depend on.

### Adding textures

Give the `Body` material a base color, roughness or normal texture in Blender,
or swap the map on the material at runtime. The UVs and tangents are already
in the GLB. The web version tints `Body` per side (`SIDE_STYLE` in
`src/pieces.ts`). A textured set would use white there or a second texture set.

## Web version layout

- `src/pieces.ts`: loads the GLBs. Each piece on the board is an `Actor` that
  owns a skinned clone and an animation mixer, crossfades the looping clip
  with the one-shot clips, and does the hop arc.
- `src/main.ts`: scene, board, picking, game flow, captures, castling,
  promotion, undo and the camera.
- `src/engine.worker.ts`: replays the game and searches with the tuichess
  engine.
- `window.web3d`: a small hook for automated checks and the console
  (`move("e2e4")`, `newGame("white", fen)`, `screenOf("e4")`, `state()`).
