## Scope and goal

This is a **size/performance engineering issue for a custom size-oriented runtime**, not a regression in Perry's default release flags and not a correctness bug. We want dependency/code-size savings without losing steady-state performance; blanket `Oz` on hot runtime code fails that requirement.

With identical public source, app O2, specialized ABI on, runtime features, system allocator, fat LTO and unwind configuration, changing only the Rust runtime/stdlib profile from O2 to Oz makes the short-scan fixture **1.78× slower for for-of** and **1.65× slower indexed**. All checksums match.

| Mode | Runtime | 5M probes median ms | Whole-process instructions, G | Instructions/cycle |
| --- | --- | ---: | ---: | ---: |
| forof | runtime O2 | 583.42 | 8.454 | 4.53 |
| forof | runtime Oz | 1038.42 | 10.973 | 3.33 |
| indexed | runtime O2 | 295.84 | 5.253 | 5.50 |
| indexed | runtime Oz | 487.08 | 5.857 | 3.73 |

Oz adds ~30% instructions to for-of and ~12% to indexed, while throughput drops. Three serial rounds, rotated runtime order; no builds/profiles concurrent. Inner time excludes setup and 100k warmup; OS counters include the whole process. This is independently reproducible without the private application that motivated the research.

## Profile and mechanism evidence

Separate eight-second samples at 1 ms, after one-second startup delay, running `forof 100000000`:

| Runtime | Total self samples | Samples in `OUTLINED_FUNCTION_*` | Share |
| --- | ---: | ---: | ---: |
| O2 | 6,002 | 0 | 0% |
| Oz | 5,955 | 1,205 | 20.24% |

The Oz profile's hottest outlined fragments include:

```asm
; OUTLINED_FUNCTION_6644: 73 self samples
ldp x20, x19, [sp], #0x20
ret

; OUTLINED_FUNCTION_1843: 66 self samples
adrp x8, <layout/TLS slot page>
ldr  x8, [x8, #0x50]
cmn  x8, #0x1
ret

; OUTLINED_FUNCTION_5241: 65 self samples
and x8, x8, #0x7fff000000000000
mov x9, #0x7ff9000000000000
cmp x8, x9
ret
```

The compiler has traded repeated inline fragments for shared callees and returns. These fragments perform necessary work too: **20.24% sampled share is not an exact estimate of removable overhead**, and this experiment does not individually separate outlining, inlining and all other O2/Oz transformations. Treat outlining as a directly observed mechanism to test, not a claim that disabling one pass recovers the entire difference.

```typescript
// Standalone synthetic reduction: short numeric-array scans behind class methods.
const STEPS: number[] = [-17, -16, -15, -1, 1, 15, 16, 17];
class ProbeBoard {
  private cells: number[] = new Array<number>(128).fill(0);
  constructor() {
    for (let i = 0; i < 128; i++) this.cells[i] = (i & 0x88) === 0 ? ((i * 3) % 7) - 3 : 0;
  }
  at(square: number): number { return this.cells[square] ?? 0; }
  probeForOf(origin: number): boolean {
    for (const delta of STEPS) {
      const square = origin + delta;
      if (square >= 0 && square < 128 && (square & 0x88) === 0 && this.at(square) === 2) return true;
    }
    return false;
  }
  probeIndexed(origin: number): boolean {
    for (let j = 0; j < STEPS.length; j++) {
      const square = origin + (STEPS[j] ?? 0);
      if (square >= 0 && square < 128 && (square & 0x88) === 0 && this.at(square) === 2) return true;
    }
    return false;
  }
}
function scan(board: ProbeBoard, iterations: number, indexed: boolean): number {
  let checksum = 0;
  if (indexed) {
    for (let i = 0; i < iterations; i++) if (board.probeIndexed(i & 127)) checksum++;
  } else {
    for (let i = 0; i < iterations; i++) if (board.probeForOf(i & 127)) checksum++;
  }
  return checksum;
}
const mode = process.argv[2] ?? "forof";
const iterations = Number(process.argv[3] ?? "5000000");
if (mode !== "forof" && mode !== "indexed") throw new Error("Expected forof or indexed");
if (!Number.isSafeInteger(iterations) || iterations <= 0) throw new Error("Expected positive iteration count");
const board = new ProbeBoard();
const warmup = scan(board, 100000, mode === "indexed");
const started = performance.now();
const checksum = scan(board, iterations, mode === "indexed");
const milliseconds = performance.now() - started;
console.log(JSON.stringify({ mode, iterations, warmup, checksum, milliseconds }));
```

### Runtime build helpers

These are provided in full because merely saying "build with Oz" is not sufficiently reproducible. Save `build-runtime.sh` and `prepare-rules.py` below in a separate experiment directory. They do not modify the supplied Perry checkout or installed runtime. The GC-effects rules adaptation adds the actual callees of two wrappers that fat LTO can fold away; it does not drop callback effects or relax unknown-call checking. The one exact unmatched `Arena::drop` teardown cut is conservatively omitted only if the analyzer diagnoses precisely that case. These compatibility details should be covered by a dedicated metadata fix; they are not performance optimizations.

#!/bin/sh
set -eu

# Run from the chess repository root. Source must match the installed Perry
# compiler. Nothing in the supplied source checkout is edited.
project_dir=$(pwd)
perry_source=$(cd "${1:?Usage: sh scripts/build-perry-small-runtime.sh /path/to/matching/perry-source}" && pwd)
case "${PERRY_SMALL_NO_REGEX:-0}" in
  0)
    runtime_dir="$project_dir/dist/perry-small/runtime"
    runtime_features="perry-runtime/keepalive-anchors,perry-runtime/regex-engine,perry-stdlib/async-bridge"
    ;;
  1)
    runtime_dir="$project_dir/dist/perry-small/runtime-no-regex"
    runtime_features="perry-runtime/keepalive-anchors,perry-stdlib/async-bridge"
    ;;
  *) echo "PERRY_SMALL_NO_REGEX must be 0 or 1" >&2; exit 1 ;;
esac
case "${PERRY_SMALL_MIMALLOC:-0}" in
  0) ;;
  1) runtime_features="$runtime_features,perry-runtime/alloc-mimalloc" ;;
  *) echo "PERRY_SMALL_MIMALLOC must be 0 or 1" >&2; exit 1 ;;
esac
runtime_dir="${PERRY_SMALL_RUNTIME_DIR:-$runtime_dir}"
profile="${PERRY_SMALL_PROFILE:-chess-small}"
profile_config="${PERRY_SMALL_CONFIG:-$project_dir/scripts/perry-small-runtime.toml}"
target_dir="${PERRY_SMALL_TARGET_DIR:-$project_dir/dist/perry-small/runtime-build}"
effects_bin="${GC_EFFECTS_BIN:-$perry_source/target/release/perry-gc-effects}"
effects_rules="${GC_EFFECTS_RULES:-$perry_source/scripts/gc_call_effects/seeds.txt}"
case "$target_dir" in /*) ;; *) target_dir="$project_dir/$target_dir" ;; esac
if [ ! -x "$effects_bin" ]; then
  echo "Set GC_EFFECTS_BIN to a matching built perry-gc-effects executable." >&2
  exit 1
fi
mkdir -p "$runtime_dir"
(
  cd "$perry_source"
  CARGO_TARGET_DIR="$target_dir" cargo --config "$profile_config" \
    build --profile "$profile" --locked -j 3 \
    -p perry-runtime-static -p perry-stdlib-static --no-default-features \
    --features "$runtime_features"
)
cp "$target_dir/$profile/libperry_runtime.a" "$runtime_dir/"
cp "$target_dir/$profile/libperry_stdlib.a" "$runtime_dir/"
if ! "$effects_bin" --root "$perry_source" --rules "$effects_rules" sidecars "$runtime_dir" > "$runtime_dir/gc-effects.log" 2>&1; then
  # Fat LTO can eliminate the standalone Arena destructor. Removing only
  # that unmatched teardown CUT is conservative; do not relax any GC seed,
  # unknown-call check, or archive fingerprint validation.
  python3 - "$perry_source" "$runtime_dir" "$effects_rules" <<'PY'
from pathlib import Path
import re
import sys
source, output, rules_path = map(Path, sys.argv[1:])
log = (output / "gc-effects.log").read_text()
expected = "teardown ^<perry_runtime::arena::block::Arena as core::ops::drop::Drop>::drop$"
unmatched = re.findall(r"^  seeds\.txt:\d+: (.+)$", log, re.MULTILINE)
if "named seed/cut rules that match NO node:" not in log or unmatched != [expected]:
    raise SystemExit("Unexpected GC effects analysis failure; inspect " + str(output / "gc-effects.log"))
rules = rules_path.read_text()
matches = [line for line in rules.splitlines(keepends=True)
           if line.startswith("teardown regex " + expected.removeprefix("teardown "))]
if len(matches) != 1:
    raise SystemExit("Expected exactly one Arena destructor teardown cut")
(output / "gc-effects-size-seeds.txt").write_text(rules.replace(matches[0],
    "# Size build: omit the unmatched Arena::drop teardown cut after fat LTO.\n"))
PY
  "$effects_bin" --root "$perry_source" --rules "$runtime_dir/gc-effects-size-seeds.txt" \
    sidecars "$runtime_dir"
fi
git -C "$perry_source" rev-parse HEAD > "$runtime_dir/source-commit.txt"
printf '%s\n' "$runtime_features" > "$runtime_dir/features.txt"
shasum -a 256 "$runtime_dir/libperry_runtime.a" "$runtime_dir/libperry_stdlib.a" > "$runtime_dir/archive-sha256.txt"
echo "Size-oriented runtime ready in $runtime_dir"

<details><summary>prepare-rules.py</summary>

```python
"""Retain callback effects when fat LTO folds two trivial forwarding wrappers."""
from pathlib import Path
import sys

source, output = map(Path, sys.argv[1:])
rules = (source / "scripts/gc_call_effects/seeds.txt").read_text()
for wrapper, targets in [
    ("js_async_hooks_provider_defer_destroy",
     "provider_ffi::(js_async_hooks_provider_defer_destroy|defer_destroy_after_check_turns)"),
    ("js_async_hooks_provider_destroy",
     "(provider_ffi::js_async_hooks_provider_destroy|destroy)"),
]:
    before = (f"indirect exact {wrapper} => exact "
              f"perry_runtime::async_hooks::provider_ffi::{wrapper} --")
    after = (f"indirect exact {wrapper} => regex "
             f"^perry_runtime::async_hooks::{targets}$ --")
    if rules.count(before) != 1:
        raise SystemExit("Unexpected callback rule; review the matching Perry revision: " + wrapper)
    rules = rules.replace(before, after)
# Both replacements ADD the known direct callee as an alternative target.
# They do not drop GC seeds, suppress unknown calls or declare a callback safe.
output.parent.mkdir(parents=True, exist_ok=True)
output.write_text(rules)
```

## Application relevance and requirements

A separate complete-app experiment (same pinned version; private source, contextual evidence only) measured the following:

- Original: **9.79 MiB**, ~5.99 s per 250k-node search.
- Blanketed app/runtime Oz plus dependency pruning: **4.43 MiB**, ~18.46 s; rejected.
- Original engine/runtime speed flags plus smaller renderer/dependencies/source metadata: **8.04 MiB**, ~5.93 s, essentially unchanged counts/timings over evaluate/legal/perft/search; full engine/CLI/terminal validation passed.
- App O2/runtime O2, minimal features, ABI on: **7.43 MiB**, search ~5.99 s but evaluation ~1.8% slower; not accepted as a no-regression build.
- App O2/runtime Os: **6.23 MiB**, evaluation ~4.0% slower; also not accepted.

The separately measured app-only Oz → O2 change recovers part of the regression; restoring runtime O2 recovers most of the remainder. Restoring mimalloc to the Oz runtime changed search by only ~1.2%, so allocator choice does not explain the large gap. Reverting only engine loop rewrites did not repair it either. Those controls distinguish the custom size regression from Perry's existing baseline overhead (#13645, #13660, #13661).

## Requested work / acceptance

- Use this fixture to isolate hot machine-outlining/inlining decisions: compare speed-optimized hot runtime functions with size optimization restricted to cold helpers, or profile-guided inlining/layout. PGO/selective hot-cold optimization is **not yet measured** here.
- Retain dependency pruning (#13659), source-metadata reduction where valid, and bounded HIR unrolling (#13649/#13650); those do not require shrinking hot code with blanket Oz.
- Report **bytes, retired instructions, cycles and wall time together**. A smaller binary with these regressions is not an acceptable solution to the requested performance-preserving size goal.
- Verify this public fixture, the regular performance suite, startup, and representative full applications including terminal/signal behavior. Preserve exceptions, unwind tables and moving-GC correctness.
- Establish version/platform coverage: these results are macOS ARM64 / M1 Max on Perry 0.5.1663. They do not prove the same magnitude on x86 or latest main; iterator work in #13653/#13655 may change the mix.

No PR proposing the slow size preset has been opened. The 4.43 MiB + original-speed combination remains unachieved.
