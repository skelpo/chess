## End-to-end results: the remaining gap

Unchanged original engine/UI source; app Os (`PERRY_LL_OPT_LEVEL=s`), specialized ABI enabled, default release runtime/stdlib features, runtime O3 / stdlib Os / ThinLTO, repository unwind flags preserved. Current artifacts use matching static-wrapper archives and regenerated GC-effects sidecars. No blanket Oz. macOS 26.5 ARM64 / Apple M1 Max, 64 GiB; Node 26.5.1, Bun 1.3.14. Node remains pinned to the earlier comparison version, rather than the newer version used in individual upstream PR tests.

Three rotated, serial rounds, after all builds completed. Inner wall time excludes setup/warmup/startup; hardware counters cover the whole process. Workload fingerprints and game-state restoration match in all 72 samples.

Current Node/Bun/ScriptC full-search medians are **950.73 / 908.80 / 1,017.19 ms**, retiring **19.324 / 17.662 / 16.724 billion instructions**. Perry remains approximately six times slower. Its ~1% search timing improvement and ~0.27% instruction reduction are effectively flat relative to the gap; three rounds do not establish a significant small timing gain. The synthetic reductions are working, but do not account for most of the full engine's instruction budget.

The pruned copy retains prior regex-free helpers, lexical signal wrappers and source-header metadata, with all five increment-spelling workarounds reverted. ## Confirmed evaluation regression requiring attribution

Evaluation is about **16% slower**. A second, longer check ran three alternating original/current pairs of 1M evaluations. Every run returns checksum 10,000,000. Raw inner times (ms):

- Original: `4578.617375, 4579.670875, 4558.181917`.
- Current: `5297.345542, 5308.606167, 5448.772708`.
- Medians: **4,578.62 → 5,308.61 ms**; retired instructions **83.826 → 86.911 G**; cycles **14.211 → 16.529 G**.

Both instruction count and cycles per instruction worsen. This is an observed integration regression, **not yet a bisected cause or a claim that one of these four PRs caused it**. These revisions contain additional changes. The private application's source is not published here, so this observation is carried as outstanding attribution work in this tracker; the separately actionable callback issue has a complete public reproduction.

## Validation and remaining work

Both current variants pass the same 875-assertion native/Node fingerprint, nine CLI scenarios including 1.5M-node search, 95 text cases, and quit/Ctrl-C/SIGTERM terminal restoration. Typechecking passes. All 150 microbenchmark samples match. Startup uses 25 launches after three discarded launches, rotated order; idle RSS uses five launches. These are warm-filesystem starts; sub-millisecond local-move changes are too noisy for strong claims.

An early attempt to combine the new compiler with old runtime archives was discarded after discovering an ABI layout change. No accepted timing data uses that arm. The accepted runtime/stdlib are built from the same pin as the compiler using `cargo build --release --locked -j3 -p perry-runtime-static -p perry-stdlib-static`, preserving the repository's nightly/unwind setup. Generated apps use all three strict flags and disabled caches. The original installed toolchain and application source remain unchanged.

Remaining work for this tracker:

1. Isolate and reduce the unchanged ~106G-instruction full-search budget; do not extrapolate synthetic probe gains to the engine.
2. Bisect the reproducible evaluation regression, then reduce the responsible case publicly.
3. Extend safe signal pruning for retained arrow identity (#13679).
4. Continue #13662's size work while gating on unchanged evaluation and search speed. The small cold-path saving is valid progress, not completion of the size/performance target.

Raw results, source/binary/archive hashes, build settings and validation logs are retained locally in `benchmarks/perry-reassessment-macos-arm64-2026-11-01.json`; earlier samples and exclusions remain separate. No PR for the slow size preset was opened or promoted.
